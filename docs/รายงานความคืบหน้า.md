## ช่องโหว่ที่พบจากการทดสอบ RLS ในฐานะผู้ใช้จริง

ทดสอบด้วย `SET ROLE authenticated` และ `request.jwt.claims` เหมือน Supabase จริง
ไม่ใช่ superuser ที่ข้าม RLS ทั้งหมด

**อาการ** นักศึกษายิง REST ตรงเข้า `/rest/v1/student_grades` เห็นคะแนนสอบปลายภาค
ก่อนอาจารย์ประกาศผล (เห็น 2 แถว: 80 และ 70 โดย 70 คือคะแนนปลายภาค)

**สาเหตุ** นโยบายของ `student_grades` ตรวจว่าแถวเป็นคะแนนปลายภาคหรือไม่ ด้วย
subquery ที่ SELECT จาก `grade_items` แต่ subquery ในนิพจน์ USING ของนโยบาย
**ถูก RLS ของตารางที่มันอ้างถึงกรองด้วย** และนโยบายของ `grade_items` ก็ซ่อนรายการ
ของหมวดปลายภาคไว้อยู่แล้ว → subquery มองไม่เห็นแถวนั้น → `NOT EXISTS` เป็นจริง
→ นโยบายอนุญาตให้อ่าน

นโยบายที่เข้มกว่าทำให้นโยบายที่ต้องพึ่งข้อมูลเดียวกันตาบอด — ยิ่งซ่อนดี ยิ่งรั่ว

**แก้แล้ว** `ee5d618` ย้ายการตรวจไปฟังก์ชัน SECURITY DEFINER สองตัวที่อ่านความจริง
ได้โดยไม่ติด RLS และเขียน `get_student_score_summary` ใหม่เป็น SECURITY INVOKER
เพื่อให้การปิดบังมีจุดบังคับเดียวคือ RLS หลังแก้: นักศึกษาเห็น 1 แถว (80)

## เรื่องที่ต้องรู้

1. **`npx tsc --noEmit` ที่ใช้ตรวจมาตลอด ไม่ได้ตรวจอะไรเลย** — `tsconfig.json` มี
   `"files": []` และมีแต่ project references ซึ่ง tsc ข้ามถ้าไม่ใส่ `-b`
   ตอนนี้ผมใช้ `npx tsc -p tsconfig.app.json --noEmit` คำสั่งที่ตรวจจริง และจะแก้
   script ให้ถูกในข้อ 3.4 ของบรีฟที่ 1
2. **`npm run lint` มี 26 error ค้างตั้งแต่ก่อนเริ่มงาน** ทั้งหมดเป็น `any` /
   `ts-ignore` ซึ่งเป็นเป้าของข้อ 3.4 วัดก่อน-หลังทุกคอมมิต งานที่ทำไม่เพิ่มแม้จุดเดียว
3. **ยังไม่ได้แยก branch ตามเฟส** ตามกฎ "หนึ่งเฟสหนึ่ง branch" — ใช้ branch เดิม
   เพราะการ deploy ดึงจาก branch นี้ ถ้าแยกจะทดสอบของใหม่ไม่ได้จนกว่าจะ merge
   แต่ละ commit แยกเฟสชัดเจนด้วยหมายเลขข้อในหัวข้อ
4. **`smartattend_web/.env` ยังอยู่ใน repo** รอคำตอบว่า Vercel ตั้ง environment
   variables ไว้แล้วหรือยัง ถ้าถอดออกก่อนตั้งจะได้หน้าจอขาว
5. **ยังไม่ deploy** มี migration ใหม่ 12 ไฟล์ที่ยังไม่ได้ `supabase db push`
