### M-00 สิทธิ์ระดับตารางของ role `authenticated`

```sql
SELECT table_name, string_agg(privilege_type, ',' ORDER BY privilege_type) AS perms
FROM information_schema.role_table_grants
WHERE grantee = 'authenticated' AND table_schema = 'public'
GROUP BY table_name ORDER BY table_name;
```

**ต้องได้** ตารางหลักทุกตัวมีอย่างน้อย `SELECT` โดยเฉพาะ `grade_audit_logs`
ซึ่งมีนโยบาย RLS ให้อาจารย์อ่านได้แต่ไม่มี `GRANT` เขียนไว้ใน migration
ถ้าตารางนี้**ไม่มี** `SELECT` แปลว่าหน้าประวัติการแก้คะแนนของอาจารย์ใช้ไม่ได้จริง

### M-02 สิทธิ์เรียก `get_scan_roster` (เกี่ยวกับ DEF-001 — วิกฤต)

```sql
SELECT p.proname,
       COALESCE(array_to_string(p.proacl, E'\n'), '(ไม่ได้กำหนด = PUBLIC เรียกได้)') AS acl
FROM pg_proc p JOIN pg_namespace n ON n.oid = p.pronamespace
```

### M-03 ยืนยันช่องโหว่ DEF-001 จากภายนอกจริง

รันบนเครื่องของตัวเอง โดยแทนค่าสองตัวจากไฟล์ `.env` ของโครงการ

```bash
curl -s -X POST \
  "$VITE_SUPABASE_URL/rest/v1/rpc/get_scan_roster" \
  -H "apikey: $VITE_SUPABASE_PUBLISHABLE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"_course_id":"<course-uuid>"}'
```

คำสั่งนี้ **ไม่ได้ส่ง token ของผู้ใช้เลย** ส่งแค่ publishable key ที่ฝังอยู่ในหน้าเว็บ

## ส่วนที่ 6 — กลุ่ม G ความปลอดภัยของ Edge Function

### G-01 เรียก Edge Function ทุกตัวโดยไม่มีสิทธิ์

ระบบมี Edge Function 7 ตัว ทุกตัวตั้ง `verify_jwt = true` ไว้ใน
`supabase/config.toml` ซึ่งหมายความว่า Supabase จะปฏิเสธคำขอที่ไม่มี token
**แต่ต้องยืนยันสองชั้น** คือชั้นที่ไม่มี token เลย และชั้นที่มี token ของผู้ใช้
ที่ไม่มีสิทธิ์ (เช่น นักศึกษาเรียกฟังก์ชันของผู้ดูแลระบบ)

**ชั้นที่ 1 — ไม่มี token เลย** รันทีละตัว แทน `<fn>` ด้วยชื่อฟังก์ชัน

```bash
for fn in admin-create-user admin-delete-user admin-review-role-request \
          parse-schedule-image import-course-roster manual-match-enrollment \
          start-class-session; do
  echo "── $fn"
  curl -s -o /dev/null -w "%{http_code}\n" -X POST \
    "$VITE_SUPABASE_URL/functions/v1/$fn" \
    -H "apikey: $VITE_SUPABASE_PUBLISHABLE_KEY" \
    -H "Content-Type: application/json" -d '{}'
done
```

**ต้องได้** `401` ทุกตัว

**ชั้นที่ 2 — มี token ของนักศึกษา** ล็อกอินเป็นนักศึกษาบนเว็บ เปิด
Developer Tools → Console แล้วรัน

```js
const { data: { session } } = await window.supabase.auth.getSession();
for (const fn of ['admin-create-user','admin-delete-user','admin-review-role-request']) {
  const r = await fetch(`${window.location.origin.replace(/.*/, '')}`, {}).catch(()=>null);
  const res = await window.supabase.functions.invoke(fn, { body: {} });
  console.log(fn, res.error?.message ?? 'ผ่านเข้าไปได้ — ต้องตรวจสอบ');
}
```

(ถ้าหน้าเว็บไม่ได้เปิด `window.supabase` ไว้ ให้ใช้วิธีคัดลอก access token จาก
`localStorage` แล้วยิงด้วย `curl` พร้อมหัวข้อ `Authorization: Bearer <token>` แทน)

**ต้องได้** ถูกปฏิเสธทุกตัว ด้วยข้อความที่บอกว่าไม่มีสิทธิ์
