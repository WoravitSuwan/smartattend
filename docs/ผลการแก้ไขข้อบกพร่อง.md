## เรื่องที่ยังต้องให้เจ้าของโปรเจกต์ตัดสินใจหรือลงมือเอง

### 1. ยืนยันสถานะฐานข้อมูลจริง (ข้อ A0 / M-01) — สำคัญที่สุด

สภาพแวดล้อมที่ใช้แก้ไม่มีคีย์เข้าถึงโปรเจกต์บนคลาวด์ และต่อเน็ตออกไป
`supabase.com` ไม่ได้ จึงตรวจของจริงไม่ได้เลย **ต้องรันเองใน SQL Editor**

```sql
SELECT p.proname, pg_get_function_result(p.oid) AS returns
FROM pg_proc p JOIN pg_namespace n ON n.oid = p.pronamespace
WHERE n.nspname = 'public' AND p.proname = 'recalc_attendance_scores';
```

ถ้าได้ `void` แปลว่าปุ่มคำนวณคะแนนการเข้าเรียนบนหน้าจอพังอยู่
(`src/lib/attendance-score-data.ts:73` อ่าน `.updated` และ `.skipped` จากผลลัพธ์)
แก้ได้ด้วยการรัน migration `20261013110000` และ `20261013120000` ตามปกติ
เพราะไฟล์ `20260927230000` ที่แก้ใน DEF-007 จะ `DROP` แล้วสร้างใหม่ให้เอง
**แต่ไฟล์นั้นถูกบันทึกว่า apply ไปแล้ว Supabase จึงไม่รันซ้ำ**
ถ้าของจริงเป็น `void` ต้องรันคำสั่งนี้ด้วยมือหนึ่งครั้ง

```sql
-- รันเฉพาะเมื่อผลข้างบนได้ void
DROP FUNCTION IF EXISTS public.recalc_attendance_scores(uuid);
-- แล้วคัดลอกนิยามฟังก์ชันจาก
-- supabase/migrations/20260927230000_attendance_score_and_cancelled_sessions.sql
-- ส่วนที่ขึ้นต้นด้วย CREATE OR REPLACE FUNCTION public.recalc_attendance_scores
-- มาวางรันต่อ
```

### 2. สั่ง VALIDATE constraint หลังนับแถวเก่า

constraint สองตัวที่เพิ่มใน `20261013120000` ใส่ `NOT VALID` ไว้
เพราะฐานข้อมูลจริงอาจมีแถวเก่าที่ไม่ผ่านเกณฑ์ ซึ่ง **ห้ามแก้หรือลบเอง**
คำสั่งนับและคำสั่ง `VALIDATE` อยู่ใน `SECURITY_NOTES.md` ข้อ 4

แถวใหม่และแถวที่ถูกแก้ตั้งแต่นี้ไปถูกบังคับทันทีอยู่แล้ว การยังไม่ `VALIDATE`
ไม่ได้ทำให้กฎไม่ทำงาน

### 3. ตัดสินใจเรื่องคีย์ในประวัติ (DEF-008)

ดู `SECURITY_NOTES.md` ข้อ 1 มีวิธีตรวจว่าคีย์ที่หลุดเป็นคีย์ชุดเดียวกับที่ใช้อยู่หรือไม่
ความเสี่ยงลดลงมากแล้วหลังแก้ DEF-001 เพราะ URL ที่เปิดเผยไม่ได้ให้สิทธิ์อะไรเพิ่ม

### 4. deploy

```bash
cd smartattend_web
npx supabase db push     # migration ใหม่ 3 ไฟล์
npx vercel --prod
```

migration ใหม่ที่จะถูก apply
`20261013100000_secure_get_scan_roster.sql` ·
`20261013110000_summary_reads_published_grade.sql` ·
`20261013120000_business_rules_at_database_layer.sql`

**หลัง deploy ให้ทดสอบสองอย่างทันที** ก่อนถึงวันสอบ
1. กดปุ่มคำนวณคะแนนการเข้าเรียนในหน้าอาจารย์ ต้องไม่ error
2. เปิดคาบเรียนแล้วให้อุปกรณ์ดึงรายชื่อ ต้องยังได้รายชื่อครบ
   (ข้อนี้สำคัญ เพราะ DEF-001 เปลี่ยนสิทธิ์การเรียก `get_scan_roster`
   ถึงจะทดสอบแล้วว่า service key ยังผ่าน แต่ควรยืนยันกับเครื่องจริง)
