# ภาพหน้าจอก่อน/หลัง ที่ความกว้าง 390px

`out/` มีภาพ 10 ไฟล์ คู่ก่อน/หลังของทั้ง 5 เรื่อง

| ไฟล์ | เรื่อง |
|---|---|
| `1-before.png` / `1-after.png` | คะแนนหมวดที่ตรวจไม่ครบ สื่อสารผิด |
| `2-before.png` / `2-after.png` | หน้าตรวจงานใช้ดรอปดาวน์ เห็นภาพรวมไม่ได้ |
| `3-before.png` / `3-after.png` | หน้ารายละเอียดรายวิชารกเกินไป |
| `4-before.png` / `4-after.png` | เมนูด้านข้างเพี้ยนเมื่อเลื่อนสุด |
| `5-before.png` / `5-after.png` | แท็บของผู้ดูแลระบบมีมากเกินไป |

ถ่ายด้วย Playwright + Chromium ที่ viewport 390 × 844 deviceScaleFactor 2
เรื่อง 4 ถ่ายแบบ fullPage เพื่อให้เห็นพื้นที่ว่างใต้เมนูในภาพ "ก่อน"

## ข้อจำกัดที่ต้องบอกให้ชัด

ภาพเหล่านี้ถ่ายจาก **harness** ไม่ใช่จากแอปที่ต่อฐานข้อมูลจริง

เหตุผล หน้าจอเหล่านี้ต้องผ่านการล็อกอินและต้องมีข้อมูลจริงในฐานข้อมูล
(รายวิชา หมวดคะแนน งาน ผลการส่งงาน) ซึ่งเครื่องที่รันงานนี้ไม่มีคีย์เชื่อมต่อ
และการยิงไปที่ฐานข้อมูลจริงของโครงงานเพื่อถ่ายภาพก็ไม่เหมาะ

harness ใช้ **CSS และ token สีชุดเดียวกับแอปจริง** (import `@/index.css`)
โครงสร้าง markup คัดลอกมาจากโค้ดที่แก้จริง ระยะห่าง ขนาดตัวอักษร และการตัดคำ
จึงตรงกับของจริง แต่ตัวเลขและชื่อเป็นข้อมูลตัวอย่าง

**ภาพที่ยืนยันเกณฑ์ตรวจรับได้ตรง ๆ คือเรื่อง 3, 4 และ 5** เพราะเป็นเรื่องของ
การจัดวางล้วน ๆ ส่วนเรื่อง 1 และ 2 ภาพแสดงรูปแบบการสื่อสารที่เปลี่ยนไป
การยืนยันด้วยข้อมูลจริงต้อง deploy แล้วถ่ายจากเครื่องจริง

## วิธีถ่ายใหม่

```bash
cd smartattend_web
npx vite --config screenshots/vite.harness.ts &     # เปิดที่ port 5199
node screenshots/shoot.mjs                          # เขียนลง screenshots/out/
```

ต้องมี Chromium ของ Playwright ถ้า path ไม่ตรงให้แก้ `executablePath` ใน `shoot.mjs`

harness ใช้ vite config ของตัวเอง จึงไม่กระทบ `npm run build` ของแอปจริง
