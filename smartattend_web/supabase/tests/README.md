# ชุดทดสอบ RPC บน PostgreSQL จริง

ทดสอบตรรกะที่บังคับอยู่ในฐานข้อมูล ซึ่งเทสต์ฝั่ง TypeScript (`npm run test`)
แตะไม่ถึง เช่น การตรวจสิทธิ์ใน `SECURITY DEFINER`, CONSTRAINT TRIGGER แบบ
`DEFERRABLE INITIALLY DEFERRED` ที่ทำงานตอน COMMIT และการตัดสินเวลาด้วย `now()`

## วิธีรัน

```bash
./supabase/tests/run.sh
```

เท่านี้ สคริปต์จะสร้างคลัสเตอร์ PostgreSQL ชั่วคราวขึ้นมาเอง รันเทสต์ แล้วลบทิ้ง
ไม่แตะฐานข้อมูลของโปรเจกต์ ไม่ต้องต่ออินเทอร์เน็ต และไม่ต้องใช้คีย์ใด ๆ

ผ่านทั้งหมดจะจบด้วย `เทสต์ผ่านครบ` และ exit code `0`
ถ้ามีข้อใดไม่ผ่าน จะพิมพ์ตารางรายการที่ไม่ผ่านแล้วคืน exit code ไม่เป็นศูนย์
ใช้ใน CI ได้ทันที

**ต้องมีในเครื่อง:** PostgreSQL 14 ขึ้นไป (ทั้ง `psql` และ `initdb`)

```bash
sudo apt install postgresql postgresql-client     # Debian / Ubuntu
brew install postgresql@16                        # macOS
```

ถ้า `initdb` อยู่ที่อื่น ระบุเองได้ด้วย `PGBIN=/path/to/pg/bin ./supabase/tests/run.sh`

### รันกับฐานข้อมูลที่มีอยู่แล้ว

```bash
DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:54322/postgres \
  ./supabase/tests/run.sh
```

> ⚠️ สคริปต์สร้างสคีมา `t` และตารางจำลองทับของเดิม แล้ว `TRUNCATE ... CASCADE`
> ระหว่างเทสต์ **อย่าชี้ไปฐานข้อมูลจริง** ใช้ได้กับฐานข้อมูลที่พังได้เท่านั้น

### `save_component_items()`

- **สิทธิ์** — คนที่ไม่ใช่ผู้สอนของรายวิชาแก้ไม่ได้
- **ความถูกต้องของข้อมูลที่เขียน** — ตั้ง `component_id` ครบทุกแถว, `position`
  เรียงตามอาเรย์, เดา `category` จาก `kind` ของหมวด (สำคัญเพราะนโยบาย RLS
  ที่ปิดบังคะแนนปลายภาคยังอ่านคอลัมน์นี้), และ **ไม่เขียน `weight` ที่เลิกใช้แล้ว**
- **ข้อมูลที่ต้องถูกปฏิเสธ** — ชื่อซ้ำในหมวดเดียวกัน, คะแนนเต็ม 0, คะแนนเต็มติดลบ,
  รายการที่ไม่ใส่ชื่อ, หมวดที่ไม่มีอยู่
- **น้ำหนักย่อยรวมไม่ถึง 100 ถูกปฏิเสธตอน COMMIT** และรายการที่ถูกปฏิเสธ
  ต้องไม่ค้างอยู่ในฐานข้อมูล
- **แก้ 60/40 เป็น 50/50 ในครั้งเดียวต้องผ่าน** — เหตุผลทั้งหมดที่ RPC นี้รับ
  ทั้งหมวดแทนที่จะรับทีละรายการ
- **ลดคะแนนเต็มแล้วมีคะแนนเกิน** — ค่าเริ่มต้นคือปฏิเสธ (ไม่ตัดสินใจแทนอาจารย์),
  `rescale` ปรับทุกคนตามอัตราส่วน, `clamp` ตัดเฉพาะคนที่เกิน
  และทุกแถวที่ถูกปรับต้องลง `grade_audit_logs` พร้อมค่าเดิมและค่าใหม่
- **กันรายการที่มีคะแนนไม่ให้ถูกลบ** — คืนชื่อมาใน `blocked` แทนที่จะลบคะแนน
  ของทั้งห้องทิ้ง
- **รายการที่ `source` ไม่ใช่ `manual`** — ชื่อและคะแนนเต็มมาจากงานที่มอบหมาย
  แก้ผ่าน RPC นี้ไม่ได้
- **คะแนนที่ถูกล็อกหลังประกาศผล** — แก้โครงสร้างไม่ได้จนกว่าจะปลดล็อก

### `record_attendance()`

- **เวลามาจาก `now()` ของฐานข้อมูลเท่านั้น** — Raspberry Pi ไม่มีนาฬิกาสำรอง
  เวลาของอุปกรณ์เชื่อถือไม่ได้ เทสต์ตรวจว่าคาบที่เพิ่งเปิดได้ `on_time`
  คาบที่เปิดมา 40 นาทีได้ `late`, `checked_in_at` ห่างจาก `now()` ไม่เกิน 5 วินาที
  และ **ฟังก์ชันไม่มีพารามิเตอร์ชนิดเวลาให้ส่งเข้ามาเลย** (ข้อหลังนี้จะพังทันที
  ถ้าวันหนึ่งมีใครเพิ่มพารามิเตอร์เวลาเข้ามา)
- **บันทึกซ้ำในคาบเดียวกัน** — คืน `already = true` ไม่ใช่ error, คืนสถานะเดิม
  โดยไม่คำนวณใหม่, ยังมีแถวเดียว และไม่เลื่อนเวลาเช็คชื่อเดิม
- **เงื่อนไขของคาบ** — คาบปิดแล้ว, คาบที่สั่งหยุดสแกน, คาบที่ไม่มีอยู่
- **เงื่อนไขของนักศึกษา** — ไม่ได้อยู่ในวิชา, ยังไม่กดยืนยันเข้าร่วม, ถูกระงับสิทธิ์
- **สิทธิ์** — `anon` บันทึกไม่ได้, นักศึกษาบันทึกแทนคนอื่นไม่ได้,
  ผู้สอนของวิชาบันทึกแทนได้ (ใช้ตอนกล้องพัง), อุปกรณ์ใช้ `service_role`
- **ค่าความเชื่อมั่น** ถูกบีบให้อยู่ในช่วง 0–1

## หลักการที่ยึดไว้

**ฟังก์ชันที่ทดสอบโหลดจากไฟล์ migration จริง ไม่ได้คัดลอกมาไว้ในเทสต์**
`save_component_items` โหลดทั้งไฟล์ ส่วน `record_attendance` ถูกดึงออกมาด้วย
`awk` จาก migration ของมัน ถ้ามีใครแก้ migration แล้วพฤติกรรมเปลี่ยน
เทสต์จะพังทันที ซึ่งเป็นสิ่งที่ต้องการ

**สคีมาในเทสต์เป็นของจำลอง** เพราะ migration ชุดเต็มพึ่ง Supabase
(`auth`, `storage`, `realtime`, นโยบาย RLS ที่อ้าง `auth.uid()`)
ยกมาทั้งก้อนใน PostgreSQL เปล่า ๆ ไม่ได้
ถ้าคอลัมน์ใน `01_stub_schema.sql` ไม่ตรงกับของจริง เทสต์จะพังด้วย
`column does not exist` — นั่นคือสัญญาณให้มาปรับไฟล์นั้น **ไม่ใช่ปรับเทสต์**

**`SET CONSTRAINTS ALL IMMEDIATE` ใน `t.raises()`**
กฎน้ำหนักย่อยรวม 100 บังคับด้วย CONSTRAINT TRIGGER แบบ `DEFERRABLE INITIALLY
DEFERRED` ซึ่งทำงานตอน COMMIT ไม่ใช่ตอนสั่ง ถ้าเรียกฟังก์ชันใน
`BEGIN/EXCEPTION` เฉย ๆ trigger จะยังไม่ทำงาน แล้วเทสต์จะผ่านทั้งที่ควรพัง
คำสั่งนี้บังคับให้ตรวจเดี๋ยวนั้น ให้ผลเหมือนตอน COMMIT จริง

## เทสต์ชุดนี้ไม่ครอบคลุมอะไร

- **นโยบาย RLS** ยังไม่ได้ทดสอบในไฟล์ชุดนี้ การทดสอบ RLS ต้อง `SET ROLE
  authenticated` พร้อมตั้ง `request.jwt.claims` และสร้างนโยบายจริงทุกตาราง
  (เคยทำด้วยมือและเจอช่องโหว่ subquery ใน `USING` มาแล้ว — ดู migration
  `20260927210000_fix_masking_rls_blind_spot.sql`) ควรเพิ่มเป็น `30_rls.sql`
  ในรอบถัดไป
- RPC อื่นที่ยังไม่มีเทสต์: `save_grade_structure_v2`, `save_student_grades`,
  `publish_final_grades`, `recalc_attendance_scores`, `cancel_class_session`
